# Safari 整頁黑屏與 WebGL 中斷提示

- **狀態：原始整頁黑屏根因未定；已實作有界 WebGL 恢復及停止循環的緩解，不能標成原始事故已修復。**
- 回報／入庫：2026-11-17（Asia/Taipei）；來源為本次協作對話及直接 Safari 監測。
- 環境：使用者電腦 Safari。使用者確認曾「整個頁面都消失，像重新開啟網站」，後回報「目前暫時正常」。兩者都保留。
- 本次核對程式基準：`b46045d`（服務台更新後的 main）；不是事故發生當時 Safari 實際載入資源的版本證明。

## 實作層：根因未定

目前沒有足夠證據將整頁黑屏歸因於 GPU 壓力、記憶體、Safari、外掛、畫質切換或網站重載。這些最多是假說。

以下為 `b46045d` 的歷史核對（本輪修改見下節）：

- 沒有定時重載整頁的 `location.reload`／meta refresh。
- 自訂處理只有 WebGL lost 提示，沒有完整的逾時、重試上限、狀態保留及失敗降級流程。
- 隨站 Three.js 本身有 `webglcontextrestored` listener；不能把「網站沒有完整恢復流程」說成「瀏覽器／Three.js 完全不能恢復」。
- `dist/resolution.js` 有動態解析度與告示牌最高畫質鎖定；存在此程式碼不等於已證實它造成閃屏。
- 告示牌畫質鎖定及險峻路可點在 PR #35／`4040da3` 已發布，不能再稱它們「尚未發布」。

## 驗證層

先前主要以隔離 Chrome 的短流程與模擬手機驗收，不能代表使用者 Safari 的長時間繪製、恢復或瀏覽器合成行為。沒有捕捉初次黑屏時的連續事件／畫面，因此缺少因果對照。沒有查到相關 crash 檔，也不代表未發生問題。

## 流程層

原本根目錄與 repo 各有 RCA 入口，但 Safari 事故沒有寫入版本化病例。後續貼入的交接文字曾把已有回報說成「沒找到紀錄」，又把已發布功能稱為未發布。防再發重點是持久化可核對事實，不是補寫一個猜測的技術根因。

## 2026-11-17 有界恢復實作與驗證

來源分支 `codex/bounded-webgl-recovery`，基準 `f5b3134`。證據及測試方法見 [驗證報告](../../research/evidence/webgl-recovery/README.md)。發布版本應以合併 PR／Git 歷史核對，不用網址查詢參數推斷。

- 首次中斷等待瀏覽器恢復，8 秒逾時或 120 秒內再次中斷，停止自動動作。這些是設計門檻，不是瀏覽器恢復時間保證。
- 恢復後固定省電設定：pixelRatio 不超過 1、關陰影及雨／彩虹；告示牌不再覆蓋低畫質。鏡頭飛行及手勢中不切解析度，鎖定有 600ms 緩衝及 16/19 距離遲滯。
- 不自動 reload。晚到的 restored 事件仍停在手動狀態，可按「重試地圖」；context 仍遺失時，只有使用者按明確標示的「手動重新整理頁面」才 reload，並用 sessionStorage 保留省電設定。卡片／清單於中斷時仍可用。
- Chrome 故障注入通過自動恢復、逾時、晚恢復手動重試、短時間重複中斷及明確手動重載。自動恢復保留鏡頭及卡片，沒有整頁重載；畫布尺寸寫入與導航事件分開記錄。
- Safari 本輪無故障注入的 localhost 對照：舊版末次取樣 67 lost／67 restored，新版為 2 lost／1 restored 並停在 manual。另做前景測試仍在主動注入前出現原生再次中斷；**Safari 成功自動恢復未通過驗證**。有界停止通過，不等於恢復成功。
- 原有 Three.js 的 lost listener 每次 preventDefault，允許瀏覽器不斷恢復；新版捕獲階段只允許第一次恢復，重複中斷時阻止其 listener 再次開啟恢復。這解釋本輪重試循環的放行條件，**不是第一次原生 context loss 或原始整頁黑屏的已證實根因**。
- 95 項單元測試通過。Safari 真實硬體故障成因、iPhone 實機及長時間成功恢復仍未驗證；不能保證完全不黑一下。

## 接力前必讀與下一步

責任者：下一位診斷／開發協作者，開始改 WebGL／畫質／恢復前，先讀本案及 `README.md`，再核對當前 `world.js`、`resolution.js` 與發布版本。

1. 確認當下是否仍發生，裝置／Safari 版本與操作路徑。不要為重現而清除資料、關閉外掛或改設定，除非得到相應授權。
2. 同時記錄整頁導航／timeOrigin、WebGL lost/restored、畫布尺寸與 pixelRatio 變更、操作與畫面，分清三類事件。臨時路徑的必要資料要去識別後入庫。
3. 修改恢復流程時保留既有上限，核對 Three.js 的事件順序，不能保證幾秒內恢復或百分之百不閃。
4. 驗收至少涵蓋恢復成功、一直不恢復、連續中斷；保留視角／卡片、沒有整頁重載迴圈。Safari 實測與失敗注入需分別標註，不互相冒充。

**關閉條件**：捕捉或可靠重現症狀、定位原因，或驗證有界緩解措施；附修正／發布版本及 Safari 實測與殘餘限制。僅「目前正常」或本次文件檢查通過，不能關閉事故。
